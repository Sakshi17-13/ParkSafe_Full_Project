# ParkSafe Setup Guide (Windows)

## 0. Install prerequisites
1. Install Node.js LTS.
2. Install Flutter SDK and Android Studio (Android SDK + emulator), then run `flutter doctor`.
3. Create a MongoDB Atlas database or run MongoDB locally.
4. For real phone-to-phone/browser calling, use HTTPS or localhost and configure STUN/TURN as required.

## 1. Start backend
Open PowerShell:
```powershell
cd D:\Projects\ParkSafe_Full_Project\backend
Copy-Item .env.example .env
npm install
```
Edit `.env` and set `MONGODB_URI` and a long random `JWT_SECRET`. Then:
```powershell
npm run dev
```
Test `http://localhost:4000/api/health`.

For a physical phone on the same Wi-Fi, `CLIENT_URL` can stay at its localhost value: the backend also permits HTTP Vite origins on private LAN IPv4 addresses at port 5173. Keep the API and website on the same computer and network.

## 2. Start visitor website
Open another PowerShell:
```powershell
cd D:\Projects\ParkSafe_Full_Project\visitor-web
Copy-Item .env.example .env
npm install
npm run dev -- --host 0.0.0.0
```
Open `http://localhost:5173`.

The visitor app adapts localhost API/socket URLs to the hostname used to open the website. For example, open `http://192.168.1.20:5173` on the visitor phone; it will call the API at `http://192.168.1.20:4000`. Allow ports 4000 and 5173 through Windows Firewall on a trusted private network. The same URL must be reachable by the phone that scans the QR; `localhost` in a QR points to the phone itself.

## 3. Prepare and run Android app
```powershell
cd D:\Projects\ParkSafe_Full_Project\owner-app
flutter pub get
flutter run
```
The Android platform files are already present. Configure `lib/config.dart` values with the optional `--dart-define` values below:
- Android emulator: `http://10.0.2.2:4000` for API and `http://10.0.2.2:5173` for visitor web.
- Physical phone: use the computer LAN IP for both API and visitor website.

The app manifest already includes Internet and microphone permissions and permits cleartext HTTP for this local demo. Use HTTPS and remove cleartext traffic for deployment.

For a physical Android phone, replace `192.168.1.20` with the computer's LAN IPv4 address and run:
```powershell
flutter run --dart-define=API_BASE_URL=http://192.168.1.20:4000 --dart-define=SOCKET_URL=http://192.168.1.20:4000 --dart-define=VISITOR_BASE_URL=http://192.168.1.20:5173
```
The QR generated by the app uses `VISITOR_BASE_URL`. The defaults in `lib/config.dart` target the Android emulator (`10.0.2.2`), so use the command above for a physical phone.

## 4. Install and launch all components (three PowerShell windows)

Run one component in each PowerShell window. Dependencies are installed with `npm install` in `backend` and `visitor-web`, and `flutter pub get` in `owner-app`. Android Studio/emulator or a USB-debugging phone must be available for `flutter run`.

Run backend route tests from `backend` with:
```powershell
npm test
```

For a physical phone scanner, browsers require a secure context for camera access. Plain HTTP on a LAN address generally cannot use `getUserMedia`; use a trusted HTTPS origin, or use the phone's native camera app to scan the QR. The website's manual link entry remains available. Browser QR decoding also depends on `BarcodeDetector` support.

## 5. Phase 1 demo
1. Run website and app.
2. Register an owner account in the app.
3. Add a vehicle with number/model/color.
4. Open View QR and scan it with a phone/browser that can reach the visitor website.
5. Confirm the vehicle details page loads.

## 6. Phase 2 demo (messages)
1. Ensure backend is connected to MongoDB.
2. Register/login in the app, then add a vehicle.
3. Open its QR page and visit the generated URL in the website.
4. Send a message from the visitor website.
5. Open Messages in the owner app and refresh; the message should appear.

## 7. Voice calling test
1. Keep the owner app open and logged in so its Socket.IO connection is active.
2. Open the vehicle URL in a separate browser/device and allow microphone access.
3. Press Call Owner; accept the incoming call in the app.
4. If audio does not connect across different networks, configure a reachable TURN service. STUN alone does not work for every NAT/network.
5. Test on real devices and HTTPS before presenting it as fully production-ready.

## Security / demo limitations
- `.env` is ignored by git. Never commit real credentials.
- Public vehicle endpoint only returns public vehicle fields; phone number is never exposed.
- Anonymous messaging has basic validation and rate limiting, but this is a student starter. Add moderation, abuse reports, stronger rate limits, logging/monitoring and HTTPS before public deployment.
- Owner replies are stored in the same message record. Visitor identity/contact information is not requested.
- Foreground call signaling is included. Background/terminated-device call notifications require FCM setup and Android call-notification handling.
- JWT is stored with `flutter_secure_storage` in the app. On web, the demo uses local storage; use a stricter production session strategy for deployment.
